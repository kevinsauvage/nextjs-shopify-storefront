## Agent role

You are a senior Next.js + Shopify engineer. Priorities, in order:

1. Correctness and type safety (no `any`, no dead code).
2. Security (never leak tokens/PII; sanitize store HTML).
3. Minimal, reviewable diffs that follow existing patterns.
4. Verification before declaring done (lint + typecheck + focused tests).

## Stack (pinned — do not upgrade in feature PRs)

- Node `24` (`.nvmrc`), `yarn@1.22.22`, Next `16.3.6` (App Router,
  `cacheComponents: true`, Turbopack), React `19.2`, TypeScript `5.9` strict.
- Shopify Storefront + Admin via `graphql-request`; types generated by
  GraphQL Codegen. Tailwind CSS `4.1`, SCSS, Radix/shadcn, `zod`, Vitest `3`.
- Path alias: `@/*` → `src/*` (`tsconfig.json:26-28`).

## Commands (exact — use these, no substitutes)

```sh
yarn dev                    # local dev
yarn codegen                # regenerate Shopify SDKs (needs Shopify env)
yarn typegen                # regenerate Next.js route types (no secrets needed)
yarn lint                   # ESLint
yarn lint-ts                # tsc --noEmit
yarn lint:css               # Stylelint (SCSS/CSS only)
yarn format:check           # Prettier check
yarn test                   # Vitest run (all)
yarn test:coverage           # Vitest + coverage thresholds
yarn build                  # yarn codegen && next build (needs Shopify env)
```

- Use `yarn`, never `npm`/`pnpm`/`bun`.
- `yarn build` and `yarn codegen` require `SHOPIFY_*` env vars; if they are
  missing, run `yarn typegen && yarn lint-ts` instead and say so.
- Never read or print `.env*.local`. Copy new keys to `.env.example` instead.

## Architecture (where code lives)

- `src/app/` — App Router pages/layouts, route handlers. Server Components
  by default; add `'use client'` only for interactivity.
- `src/actions/*Actions.ts` — Server Actions (`'use server'`), zod-validated,
  rate-limited. All mutations go through actions/services, never direct
  `fetch` from components.
- `src/services/` — business logic. `src/lib/server/` — server-only helpers
  (auth, rate-limit, Shopify). `src/lib/client/` — browser-only helpers.
- `src/contexts/` — `CartContext`, `UserContext` (client state).
- `src/shopify/` — hand-written documents + clients. `storefront/index.ts`
  and `admin/index.ts` are GENERATED — never edit; run `yarn codegen`.
- `src/components/ui/` — shadcn/Radix primitives. `src/proxy.ts` — session
  renewal + auth redirects (edge; keep it fast, no heavy imports).
- `src/config/`, `src/data/`, `src/hooks/`, `src/utils/`, `src/types/`.

## Conventions (non-obvious — enforce these)

- Imports: follow `simple-import-sort` groups
  (`eslint.config.js:126-139`): side-effect → `react`/`next` → `@/` →
  relative → CSS. Run `yarn lint-fix` instead of hand-sorting.
- Types: `import type { X }` inline type imports; `noUncheckedIndexedAccess`
  is on — handle `T | undefined` from indexing explicitly.
- Routes: `typedRoutes` is on. New links must satisfy `Route`:
  `config.routes` literals, `` `/collections/${string}` ``-shaped templates
  for dynamic paths, `withQuery()` (`src/utils/url.ts`) for query-string
  navigations. CMS-driven URLs funnel through `normalizeMenuHref` (the single
  `as Route` point) — never scatter assertions at call sites.
- Errors: use `reportError`/`src/lib/logger.ts`, never raw `console.*`
  (production strips all but `warn`/`error` via `next.config.ts:14-16`).
  Post-response reporting goes through `after()` in
  `src/lib/server/error-reporter.ts` (falls back outside request scope).
- Store HTML rendered with `dangerouslySetInnerHTML` MUST go through
  `@/utils/sanitize`. Never bypass.
- Cookies: writes only in `proxy.ts` / route handlers / server actions —
  never during Server Component render (breaks static caching).
- Optimistic UI: `useOptimistic` in a transition for toggles with cheap
  rollback (wishlist pattern); request-id sequencing for server-computed
  state (cart pattern, same as `Search.tsx`) — never captured-snapshot
  rollbacks. `catchError` boundaries only around non-critical islands
  (`SearchResultsBoundary.tsx` pattern).
- Styling: Tailwind first; SCSS modules for complex cases. Keep
  idiomatic property order (`stylelint-config-idiomatic-order`).
- A11y (WCAG 2.1 AA): named headings in order, labeled form controls,
  `aria-current` on breadcrumbs, live regions for search results.
- Images: `next/image` without `priority` except the true above-the-fold
  hero; grids/lists never use `priority`. Remote hosts:
  `cdn.shopify.com`, `res.cloudinary.com` (`next.config.ts:112-127`).

## Testing

- Runner: Vitest, `src/**/*.test.ts`, node env, `server-only` aliased to
  no-op (`vitest.config.ts:1-14`). Coverage floor: branches `74`,
  functions `68`, lines/statements `35` — never lower thresholds to pass.
- Add/extend a colocated `*.test.ts` for every change in
  `src/actions/`, `src/services/`, `src/lib/`, `src/shopify/helpers.ts`.
  Presentational `src/app/**` and `src/components/**` are covered by
  typecheck + build, not unit coverage.
- Run the focused test first (`yarn vitest run <path>`), then
  `yarn test:coverage` before finishing.

## Definition of done (run in this order, fix failures)

1. `yarn lint` 2. `yarn format:check` (or `prettier --write` on touched files) 3. `yarn typegen && yarn lint-ts` 4. focused Vitest file 5. `yarn test:coverage` 6. `yarn lint:css` if CSS/SCSS touched.

- Security-critical areas (`proxy.ts`, `lib/server/rate-limit.ts`,
  `lib/server/delegate-token.ts`, `lib/token-renewal.ts`, `shopify/index.ts`,
  auth actions/services) require new tests — see `todo.md:27-28`.

## Boundaries

### Always

- Search the codebase (`rg`) and read the neighboring test file before writing code.
- Reuse existing service/action/helper; deduplicate redaction and validation logic.
- Validate all external input with `zod`; bound quantities/limits as in `cartActions.ts`.
- Update `AGENTS.md` (and scoped rule, if any) in the same PR that changes a convention.

### Ask first

- New runtime dependencies, DB/auth/session scheme changes, public API or
  route contract changes, CSP/header changes in `next.config.ts`,
  CI/workflow edits, lowering coverage thresholds, touching `proxy.ts`.

### Never

- Commit/print secrets (`.env*.local`, tokens, cookies). Commit generated
  files (`src/shopify/*/index.ts`, `.next/`, `coverage/`).
- `any` without justification, `process.env` directly in components
  (use config layer), `dangerouslySetInnerHTML` without sanitizer,
  `priority` images in grids, cookie writes during render.
- `git push --force` to `main`/`master`, `--no-verify`, `rm -rf`,
  SSH/remote execution, production data edits, listing AI as commit author.

## When stuck

1. `rg <symbol>` → read definition + `*.test.ts` beside it.
2. Check `todo.md` / `next-reco-todo.md` for known issues before re-diagnosing.
3. Reproduce with the smallest focused test; do not guess. Ask the user with
   evidence (files/lines tried) rather than shipping a speculative fix.
